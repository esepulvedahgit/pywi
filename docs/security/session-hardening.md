# Sesiones, acceso y páginas de error

PyWI autentica el navegador con una cookie `HttpOnly; SameSite=Lax; Path=/`. Si `APP_URL` comienza con `https://`, añade `Secure`; configure esa URL con el origen público exacto servido por Nginx, Sophos u otro proxy TLS. El tráfico entre el proxy y la aplicación puede usar HTTP por una red privada. El puerto 3000 se publica solo en `127.0.0.1` por defecto. Si el proxy está en otro host, configure `PYWI_BIND_IP` con la IP privada de PyWI, `TRUSTED_PROXY_IPS` con la IP exacta del proxy, y permita el puerto 3000 solo desde esa IP en el firewall. Configure el proxy para sobrescribir cualquier `X-Forwarded-For` enviado por el cliente. La cookie dura como máximo siete días y el servidor bloquea la sesión tras diez minutos sin actividad humana. Las solicitudes de fondo, métricas y sondeos no renuevan el tiempo de inactividad. El botón de bloqueo y el cierre de sesión afectan solo al dispositivo actual. Un cambio o restablecimiento de contraseña invalida todas las sesiones.

Las sesiones y los retrasos de acceso se guardan en el volumen `/app/data`. El archivo de sesiones contiene hashes SHA-256 de los identificadores, nunca las cookies en claro. Al actualizar desde versiones JWT, los usuarios deben iniciar sesión de nuevo. Puede retirar `JWT_SECRET` de `.env`; `ENCRYPTION_KEY` debe ser exactamente 64 caracteres hexadecimales y conservarse entre despliegues. Si su clave anterior **no** era hexadecimal, la versión previa aplicaba SHA-256 a su texto: conviértala al digest hexadecimal de SHA-256 antes de actualizar para conservar la capacidad de descifrar las API keys ya guardadas. Puede calcularlo sin dejar la clave en el historial con `python3 -c 'import getpass, hashlib; print(hashlib.sha256(getpass.getpass("Clave anterior: ").encode()).hexdigest())'`.

El navegador envía un token CSRF en las operaciones que modifican datos; el servidor también comprueba que `Origin` coincida con `APP_URL`. Las llamadas a `/api` de clientes sin navegador ya no son compatibles. Los artefactos generados y WebSocket requieren la misma sesión; no se admiten tokens de **sesión** en URL. Los enlaces de restablecimiento de contraseña siguen usando un token de recuperación en la URL que expira a los quince minutos; la política `Referrer-Policy: no-referrer` evita que se envíe a otros sitios. El inicio de sesión aplica un límite por IP y una espera progresiva por cuenta de 30 a 900 segundos desde el quinto fallo en quince minutos. `X-Forwarded-For` solo se acepta si la IP de conexión está enumerada en `TRUSTED_PROXY_IPS`, por ejemplo `TRUSTED_PROXY_IPS=10.0.0.5`. No use comodines. Configure Sophos para sobrescribir cualquier `X-Forwarded-For` enviado por el cliente antes de añadir la IP real.

Las rutas desconocidas de `/api` devuelven JSON 404; las páginas inexistentes muestran HTML 404, y los errores internos muestran HTML o JSON 500 sin trazas. Los errores 400/413 de cuerpo inválido también se responden sin detalles internos. Las páginas y respuestas genéricas de API admiten inglés y español según `Accept-Language`. Las respuestas incluyen CSP, protección contra marcos, `nosniff`, política de referencias y HSTS cuando la URL pública es HTTPS.

Para verificar después del despliegue: abra `/ruta-inexistente` y `/api/ruta-inexistente`; inspeccione `Set-Cookie` tras iniciar sesión y `Cache-Control: no-store` en `/api/auth/session`; bloquee una pestaña y compruebe que el otro dispositivo siga activo; cambie la contraseña y confirme que ambos dispositivos deban volver a iniciar sesión. La renovación de actividad se produce por interacción del usuario, no por sondeos automáticos.
